## Design Specificity Verdict
System is authored and disciplined (hand-picked tokens, Material-3 rejection, named rules, drift test). But the Walls screen contradicts its own system: displayListCard/epaperListCard/defaultCard (admin.ts:3489-3563) bypass the component vocabulary and hand-type inline-style div trees. The newest, most-unified screen reached for raw markup instead of listRow()/card().

Deterministic scan: detect.mjs exits 2 with 13 findings — all color/font-size/radius/overused-font regex hits (admin-shifts.ts:38-40, booting-page.ts:40, html.ts #fff x3, border-radius:2/3, 'Roboto'). None button-related; the detector's 51-rule registry has no button-consistency rule, and structural rules need real DOM the string-concat source cannot give. The project's own admin-component-drift.test.ts is blind the same way (scans stylesheet text, not inline style= on route output). The bug the user spotted by eye is invisible to both automated checks.

## Priority Issues

[P0] The Walls action row is three broken things at once (the "looks broken").
In epaperListCard (admin.ts:3529-3537) one raw flex div holds three siblings at three sizes and three vertical offsets:
1. <a class="btn">Design layout — filled, correct (40px, margin-top:24px).
2. <a class="btn-ghost">URL & recipes (admin.ts:3533) — THE BUG. Base button anatomy (height/padding/radius/inline-flex/text-decoration:none/48px ::after) comes only from selector button,.btn (html.ts:795). A bare <a class="btn-ghost"> matches neither, so it gets only color/border-color and renders as plain underlined accent text (no height, margin-top:0). Only place in src/http where .btn-ghost sits on an anchor without .btn; correct pattern at admin.ts:981-982 uses "btn btn-ghost btn-sm".
3. <form method="get"><button class="btn-danger">Remove — this is why Remove sits lower than Design layout. Design layout is a direct flex child and gets margin-top:24px on itself; Remove is wrapped in a <form> (the flex child, margin-top:0) and the button inside carries the 24px, dropping it ~24px below its neighbor. Broken ghost link in the middle (align-items unset, default stretch) disrupts baseline further. Three items, three heights, three offsets — mechanically.
Fix: (1) class="btn btn-ghost" at admin.ts:3533. (2) Route Remove through destructive(). (3) Replace inline style with shared .row (row button{margin-top:0} normalizes baseline). (4) One identical action convention across browser and e-paper cards.
Command: /impeccable layout

[P1] Walls cards are hand-typed markup that bypasses the component layer.
defaultCard/displayListCard/epaperListCard (admin.ts:3489-3563) build inline-style div trees (gap:12px/10px, margin-top:10px, font-size:16px) instead of card()/listRow()/tag(); 10px maps to no token. Drift test scans stylesheet not inline style=, so this drift is invisible to its own guard. Root cause of P0.
Fix: rebuild on listRow()/card(); delete inline styles. listRow() already solves this shape and is used in 9 other lists, never Walls.
Command: /impeccable extract (or layout)

[P1] Four distinct treatments for one semantic action; three card-footer conventions.
Navigate rendered four ways: whole-card <a class="card"> with decorative <span class="link">Open (admin.ts:3502,3562); filled .btn CTA (3532); broken unstyled ghost link; tested <a class="mw-row-link"> via listRow() in 9 other lists but never Walls. Destroy lives three ways: ⋮ overflow on Calendars (with a comment on why), standalone danger on Shifts, bare form-button on Walls. .tonal/.btn-tonal defined and used zero times.
Fix: standardize on Calendars' ⋮-menu destroy, one navigation treatment per card, promote card-footer action row to a component; delete or use .tonal.
Command: /impeccable layout

[P2] "Open" is a <span>, not a link — no affordance, wrong focus ring.
<span class="link">Open matches only bare .link (inline-flex;gap); accent color/weight live on a.link (html.ts:525) which a span never matches, so it renders in plain ink. a.card is absent from the focus-ring selector list (html.ts:2248), so keyboard focus draws the UA outline, not the --mw-accent ring.
Fix: use the accent-styled .link idiom; add a.card to focus-visible list.
Command: /impeccable clarify + /impeccable audit

[P2] Walls' Remove reintroduces the "eight rows of Remove" a11y problem destructive() was built to kill.
Bypassing destructive() means accessible name is bare "Remove", no aria-label naming the wall (components.ts:429-430). The broken "URL & recipes" link never gets the 48px ::after touch-target, so its hit area is under the 44px --mw-touch minimum.
Fix: route Remove through destructive() (fixes label and element-type mismatch at once).
Command: /impeccable harden
